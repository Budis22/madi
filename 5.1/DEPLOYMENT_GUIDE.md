# Руководство по развёртыванию

Проект — **статический SPA** после `npm run build` (папка **`dist/`**). Отдельный бэкенд для текущего MVP **не нужен** (логика и моки в браузере).

---

## Что сделать до деплоя

1. Локально сборка без ошибок:

   ```bash
   cd /путь/к/module_5.1
   npm install
   npm run build
   ```

2. Код в репозитории на **GitVerse** (ветка **`main`**, актуальные коммиты).

3. Если в корне GitVerse лежит **не** этот проект, а монорепо с подпапкой — на шагах ниже укажите **Root directory** / **Base directory** = подпапка с `package.json` (например `module_5.1`).

---

## Вариант A — Vercel (удобно для SPA)

### Шаг 1. Аккаунт

Зайдите на [vercel.com](https://vercel.com), зарегистрируйтесь (можно через GitHub / GitLab — если GitVerse не в списке, используйте email или привяжите репозиторий через зеркало / импорт; часто студенты заливают тот же код на GitHub **или** подключают Git по URL, если Vercel это поддерживает в вашем регионе).

Если Vercel **не** видит GitVerse напрямую:

- либо добавьте **remote** на GitHub и пушьте туда же копию для деплоя;
- либо используйте **Netlify** (часто проще с произвольным Git).

### Шаг 2. Новый проект

1. **Add New… → Project**.
2. **Import** нужный Git-репозиторий (или загрузите папку через CLI `vercel`, если без Git).

### Шаг 3. Настройки сборки

| Поле | Значение |
|------|----------|
| Framework Preset | **Vite** (или Other, если не определил) |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | `npm install` |
| Root Directory | оставьте пустым **или** укажите подпапку с `package.json` |

### Шаг 4. Деплой

Нажмите **Deploy**. После сборки Vercel выдаст URL вида `https://….vercel.app`.

### Шаг 5. SPA и маршруты

В корне уже есть **`vercel.json`** с правилом «все пути → `index.html`», чтобы при обновлении страницы на `/admin` не было **404**.

Если что-то не открывается — проверьте, что `vercel.json` попал в репозиторий и в деплой.

### Шаг 6. Продакшен

Каждый `git push` в подключённую ветку обычно запускает **новый деплой** (Preview / Production — по настройкам проекта).

## Вариант B — Netlify

### Шаг 1. Сайт из Git

1. [app.netlify.com](https://app.netlify.com) → **Add new site** → **Import an existing project**.
2. Подключите репозиторий (GitVerse через провайдера или зеркало на GitHub — как получится у вас в UI).

### Шаг 2. Настройки сборки

| Поле | Значение |
|------|----------|
| Build command | `npm run build` |
| Publish directory | `dist` |
| Base directory | при необходимости подпапка с проектом |

### Шаг 3. SPA-редиректы

В проекте уже есть **`public/_redirects`**:

```txt
/*    /index.html   200
```

Vite копирует `public/` в `dist/`, поэтому после деплоя **Netlify** отдаёт `index.html` для любых путей — маршрут `/admin` работает после перезагрузки.

### Шаг 4. Деплой

Сохраните настройки → сайт получит URL `https://….netlify.app`.

## Service Worker (после деплоя)

- `public/sw.js` попадает в **`dist/sw.js`**.
- Регистрация в **`src/main.js`** только при **`import.meta.env.PROD`** — на **production**-URL сервис-воркер включится.

Проверка: откройте сайт → Chrome DevTools → **Application** → **Service Workers** → должен быть активный worker. Иногда нужно **второе** открытие вкладки или минута на активацию.

## Бэкенд / LLM-прокси (опционально)

В текущем MVP **нет** серверного кода: намерения на клиенте. Если позже добавите OpenAI:

1. Поднимите минимальный Node/Express на [Render](https://render.com) или [Railway](https://railway.app).
2. Храните `OPENAI_API_KEY` в переменных окружения **сервера**, не в репозитории.
3. Фронтенд вызывает только ваш прокси (`POST /assistant`).

---

## Переменные окружения

Для текущего MVP **не обязательны**. Если добавите API:

```env
VITE_ASSISTANT_URL=https://your-proxy.example.com
```

В панели Vercel/Netlify: **Settings → Environment Variables**, затем **пересоберите** проект.

---

## После успешного деплоя (чеклист)

1. Откройте **главную** — карта и чат работают.
2. Откройте **`/admin`** — админ-панель открывается.
3. Вставьте **публичный URL** в:
   - `README.md` (блок «Живой сайт»);
   - `FINAL_REPORT.md` (раздел «Демо»), если сдаёте отчёт.
4. Сделайте **`git add` → `commit` → `push`**, чтобы ссылки уехали на GitVerse.

## Типичные проблемы

| Симптом | Что проверить |
|--------|----------------|
| 404 на `/admin` после F5 | `vercel.json` (Vercel) или `_redirects` в `public/` (Netlify) |
| Пустая страница | Логи сборки: не упал ли `npm run build`, верно ли указан `dist` |
| Старый фронт после push | Дождаться окончания деплоя; сброс кэша CDN (редко) |
| SW не регистрируется | Открыт ли именно **production**-URL, а не сырой `index.html` с диска |

```bash
npm run build
npm run preview
```
